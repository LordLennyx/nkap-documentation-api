Documentation développeur

Encaissez par carte, wallet et Mobile Money avec une seule API.

L'API Nkap est une API REST : URL orientées ressources, corps JSON, codes HTTP standards et authentification par clé. Chaque exemple de cette page fonctionne dans la console à droite, en mode test, sans créer de compte.

URL de base : https://api.nkap.io/v2. Les montants sont exprimés en centimes : 4900 signifie 49,00 €.

Authentification

Envoyez votre clé secrète dans l'en-tête Authorization. Les clés de test commencent par sk_test_ et n'effectuent aucun mouvement réel. Ne publiez jamais une clé secrète dans du code côté navigateur.

Clé de démonstration utilisable dans la console : sk_test_nkap51DemoQx8Lm2Vb7Ty

Premier paiement en 5 minutes

Créez le paiement côté serveur

Appelez POST /payments avec le montant, la devise et le numéro du payeur.

Le client confirme sur son téléphone

Il reçoit une demande de validation et saisit son code. Le statut passe de pending à succeeded.

Recevez le webhook

Nkap appelle votre URL avec l'événement payment.succeeded. Livrez la commande à ce moment-là, pas avant.

Créer un paiement

POST/v2/payments

Crée une demande de paiement. Pour le Mobile Money, le payeur reçoit une notification de confirmation ; pour la carte, l'URL redirect_url renvoie vers la page 3-D Secure.

Paramètres du corps

amountentierrequis

Montant en centimes, entre 50 (0,50 €) et 1 000 000 (10 000 €).

currencychaînerequis

Code ISO 4217. EUR par défaut ; GBP et CHF sont aussi acceptés.

methodchaînerequis

mobile_money ou card.

phonechaîne

Numéro du payeur au format international, requis pour mobile_money.

descriptionchaîne

Libellé affiché sur le relevé du client, 60 caractères au plus.

metadataobjet

Jusqu'à 20 paires clé-valeur pour relier le paiement à votre commande.

En-tête facultatif

Idempotency-Keychaîne

Rejouer une requête avec la même clé renvoie le même paiement au lieu d'en créer un second.

Consulter un paiement

GET/v2/payments/:id

Renvoie un paiement à partir de son identifiant. Utile pour vérifier un statut si un webhook n'a pas été reçu.

Lister les paiements

GET/v2/payments

Renvoie les paiements du plus récent au plus ancien, paginés par curseur.

Paramètres de requête

limitentier

Entre 1 et 100, 10 par défaut.

statuschaîne

Filtre : pending, succeeded, failed, refunded.

Rembourser

POST/v2/payments/:id/refund

Rembourse tout ou partie d'un paiement réussi. Le remboursement est crédité sur le moyen de paiement d'origine.

Paramètres du corps

amountentier

Montant à rembourser ; le total par défaut.

Créer un client

POST/v2/customers

Enregistre un client pour réutiliser ses moyens de paiement et suivre son historique.

Paramètres du corps

namechaînerequis

Nom complet.

phonechaînerequis

Numéro au format international.

emailchaîne

Adresse électronique pour l'envoi des reçus.

Supprimer un client

DELETE/v2/customers/:id

Supprime définitivement un client. Les paiements passés restent consultables.

Webhooks

Nkap envoie une requête POST signée à votre URL pour chaque événement. Vérifiez la signature Nkap-Signature (HMAC SHA-256 du corps avec votre secret de webhook) et répondez 200 en moins de 10 secondes ; sinon l'envoi est retenté pendant 72 heures.

ÉvénementQuand
payment.succeededLe payeur a confirmé et les fonds sont réservés.
payment.failedRefus, solde insuffisant ou délai dépassé.
refund.createdUn remboursement a été émis.
customer.deletedUn client a été supprimé.

Codes d'erreur

Les erreurs renvoient un objet error avec un code stable, un message lisible et le paramètre en cause.

HTTPCodeSignification
400parameter_invalidUn paramètre est absent ou mal formé.
401authentication_failedClé absente, inconnue ou révoquée.
402insufficient_fundsLe compte du payeur est insuffisant.
404resource_missingL'identifiant n'existe pas.
409idempotency_conflictMême clé d'idempotence, corps différent.
429rate_limitedPlus de 100 requêtes par seconde.
